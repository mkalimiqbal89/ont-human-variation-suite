# ONT Epi2ME Structural Variant Categorization Pipeline

A reproducible pipeline for categorizing structural variants (SVs) from Oxford
Nanopore long-read whole-genome sequencing, processed through Epi2ME Labs'
`wf-human-variation` workflow. Filters and splits Sniffles2-called SVs into
deletions, insertions, duplications, inversions, translocations, and
SnpEff-confirmed gene fusions/disruptions.

## What this pipeline does

Epi2ME's `wf-human-variation` outputs structural variants as a single
Sniffles2 VCF (`<prefix>.wf_sv.vcf.gz`), annotated with SnpEff if
`annotation: True` was set for the run. This pipeline:

1. Validates that VCF and the reference bundle are present and readable.
2. Flattens the VCF into an analysis-ready TSV, extracting only scalar
   fields (never raw ALT sequence or full annotation blocks, which can be
   many KB per record for long insertions).
3. Applies QC thresholds (quality, read support, VAF, SV length) and splits
   PASSing variants into one TSV per SV category.
4. For `BND` (breakend/translocation) records, trusts and extracts SnpEff's
   own breakpoint-effect classification (`bidirectional_gene_fusion`,
   `feature_fusion`, `transcript_ablation`, etc.) rather than re-deriving
   fusions from coordinates — producing a confirmed gene-fusion table and a
   separate gene-disruption table.

**What it does not do:** call SVs (that's Sniffles2/Epi2ME's job), do CNV or
SNV analysis (separate VCFs from Spectre/Clair3 exist in the same Epi2ME
output but are out of scope for this pipeline), or attempt fusion detection
independent of SnpEff's annotation (see `docs/METHODS.md` for why).

## Repository structure

```
config/
  pipeline_config.yaml     # sample ID, paths, filtering thresholds — EDIT PER RUN
  reference_paths.yaml     # genome/annotation reference bundle — EDIT PER RUN
scripts/
  bash/
    00_setup_env.sh              # sourced by every other script; checks tools, exports config
    01_validate_inputs.sh        # confirms VCFs + reference files are present and valid
    02_vcf_to_tsv.sh              # flattens Sniffles2 SV VCF -> TSV
    03_filter_sv_categories.sh    # QC filtering + splits into per-category TSVs
    04_run_all.sh                 # runs 01->02->03->05->06->07 end-to-end, aborts on first failure
    08_archive_results.sh          # copies results to internal institutional storage (NOT git-tracked; not part of 04_run_all.sh)
  R/
    05_annotate_variants.R        # resolves gene fusions/disruptions from BND ANN data
    06_summary_stats.R            # aggregates per-category summary statistics
    07_generate_report.R          # generates overview figures (PNGs) across all SV types
data/
  raw/          # symlink or copy Epi2ME output here (gitignored — never commit sequencing data)
  processed/    # intermediate flattened TSVs (gitignored, regenerated by the pipeline)
results/
  deletions/ insertions/ duplications/ inversions/ translocations/
  complex_rearrangements/ gene_fusions/ qc_summary/
logs/           # timestamped logs per script run + tool_versions.txt
docs/
  METHODS.md            # detailed rationale for filtering/classification choices
  TROUBLESHOOTING.md    # common errors and fixes encountered during development
```

## Requirements

- `bcftools` >= 1.20, `bedtools` >= 2.31, `tabix`/`htslib`
- R >= 4.3 with the `yaml` package (`install.packages("yaml")` or
  `conda install -c conda-forge r-yaml`)
- A local conda/mamba environment is recommended; see `environment.yml`.
  If your tools live behind `module load` on an HPC instead, load them
  before running any script (`00_setup_env.sh` will tell you if something's
  missing or broken).

## Setup

1. Clone this repository.
2. Edit `config/pipeline_config.yaml`:
   - `sample.sample_id` — the **anonymized** identifier used in every output
     filename this pipeline generates.
   - `sample.raw_sample_prefix` — the actual filename prefix Epi2ME used for
     this sample's output files (never propagated into results — it exists
     solely so the pipeline can locate the real input files on disk).
   - `paths.input_dir` — the Epi2ME `wf-human-variation` output directory
     for this sample.
   - `paths.output_dir`, `paths.work_dir`, `paths.repo_dir` — where this
     pipeline writes results, scratch files, and where the repo itself
     lives.
   - `filtering.*` — QC thresholds. Defaults are permissive (matching what
     Epi2ME/Sniffles2 already enforce); see `docs/METHODS.md` for guidance
     on tightening these for germline vs. mosaic/somatic analyses.
3. Edit `config/reference_paths.yaml`:
   - `genome.fasta` / `genome.fasta_index` — must match the genome build
     Epi2ME aligned against (GRCh38 by default).
   - `annotation.gene_bed` — a gene-model BED file (used as a secondary
     cross-check; SnpEff annotation embedded in the VCF is primary — see
     `docs/METHODS.md`).
4. Confirm your actual Epi2ME output filenames match what's in
   `input_files:` in the config — naming can vary slightly by Epi2ME
   version:
   ```bash
   find "$INPUT_DIR" -iname "*.vcf.gz"
   ```

## Running

Run everything in one command:

```bash
bash scripts/bash/04_run_all.sh
```

Or run steps individually (useful when developing/debugging one step):

```bash
bash scripts/bash/01_validate_inputs.sh
bash scripts/bash/02_vcf_to_tsv.sh
bash scripts/bash/03_filter_sv_categories.sh
Rscript scripts/R/05_annotate_variants.R
```

Every script accepts an optional config path as its first argument if you
want to run against a config file other than the default
`config/pipeline_config.yaml`:

```bash
bash scripts/bash/04_run_all.sh config/pipeline_config_sample02.yaml
```

## Expected outputs

| File | Contents |
|---|---|
| `data/processed/<sample_id>.sv_flat.tsv` | All SV records, flattened, pre-filtering |
| `results/deletions/<sample_id>.deletions.tsv` | QC-passing `DEL` records |
| `results/insertions/<sample_id>.insertions.tsv` | QC-passing `INS` records |
| `results/duplications/<sample_id>.duplications.tsv` | QC-passing `DUP` records |
| `results/inversions/<sample_id>.inversions.tsv` | QC-passing `INV` records |
| `results/translocations/<sample_id>.translocations.tsv` | QC-passing `BND`/`TRA` records |
| `results/gene_fusions/<sample_id>.gene_fusions.tsv` | Confirmed gene fusions (SnpEff-classified) |
| `results/gene_fusions/<sample_id>.gene_disruptions.tsv` | Single-gene breakpoint disruptions (not fusions) |
| `results/gene_fusions/<sample_id>.fusion_annotation_full.tsv` | Every BND record with its classification, for audit |
| `results/qc_summary/<sample_id>.filtering_summary.tsv` | Per-category variant counts before/after filtering |
| `logs/tool_versions.txt` | Exact tool versions used — copy into your methods section |
| `logs/<script>_<timestamp>.log` | Full stdout/stderr of every run, timestamped |

## A note on gene-fusion calling

This pipeline **does not** independently pair `BND` mate breakpoints and
intersect them against a gene BED to call fusions from coordinates alone.
Instead it trusts SnpEff's own breakpoint-effect annotation, already present
in the VCF if the Epi2ME run was configured with `annotation: True`. This is
a deliberate design choice, not a shortcut — see `docs/METHODS.md` for the
full rationale, including a real example from pipeline development where a
gene pair was only recoverable from the second of two comma-separated
annotation blocks on the same record.

If your Epi2ME run was **not** annotated with SnpEff (`annotation: False`),
`05_annotate_variants.R` will report all `BND` records as `unannotated` —
this is expected, not a bug; re-run Epi2ME with `--annotation` or perform
fusion calling with a separate tool.

## Reproducing on a new sample

1. Copy `config/pipeline_config.yaml` to something sample-specific (e.g.
   `config/pipeline_config_<new_sample>.yaml`) and edit the `sample:` and
   `paths:` sections. `reference_paths.yaml` typically does not need to
   change between samples of the same species/build.
2. Run `bash scripts/bash/04_run_all.sh config/pipeline_config_<new_sample>.yaml`.
3. No other files need editing — this is the entire point of parameterizing
   paths through the config rather than hardcoding them in scripts.

## Troubleshooting

See `docs/TROUBLESHOOTING.md`. Common first checks:

- `bash scripts/bash/01_validate_inputs.sh` fails on tool checks: confirm
  you've activated the correct conda environment (`conda activate
  vcf_tools` or equivalent) — a tool being installed somewhere on the
  system is not the same as it being on `PATH` in your current shell.
- Filenames not found: Epi2ME output naming varies by version; run
  `find $INPUT_DIR -iname "*.vcf.gz"` and update `input_files:` in
  `pipeline_config.yaml` to match exactly.
- Zero variants after filtering when you expected some: check
  `results/qc_summary/<sample_id>.filtering_summary.tsv` and compare against
  the pre-filter count in `data/processed/<sample_id>.sv_flat.tsv` to see
  which threshold is responsible.

## Testing

`tests/run_tests.sh` runs the full pipeline against a small, hand-crafted
synthetic VCF (`tests/fixtures/test_sample.wf_sv.vcf.gz`) with known expected
outcomes — one record per SV category, a sub-threshold record per filter (to
confirm filtering actually excludes it), and the real `BND`/`ANN` edge cases
found during development (a gene pair recoverable only from the *second* of
several comma-separated annotation blocks; the same fusion called twice at
nearby breakpoints, to confirm duplicate-event flagging). It asserts exact
output counts and specific content, not just "did it crash":

```bash
bash tests/run_tests.sh
```

Run this after modifying any script — it's the fastest way to catch a
regression before it reaches real data. It runs in seconds against ~30
lines of synthetic data.

## Keeping identifying data out of git

This pipeline is part of the [ONT Human Variation Suite](../../README.md); the
repository already exists, so there is nothing to initialise. What matters is
that real data never gets committed:

- `config/pipeline_config.yaml` and `config/reference_paths.yaml` — the real,
  per-sample/per-machine files with actual sample identifiers and absolute local
  paths — are gitignored by `pipelines/sv/.gitignore`.
- `config/pipeline_config.example.yaml` and `config/reference_paths.example.yaml`
  (sanitised templates) are tracked and are what a fresh clone starts from.

The ignore rules live beside the pipeline, not at the suite root, because a
gitignore pattern containing a slash is anchored to the directory holding the
file. When this pipeline was first moved into `pipelines/sv/`, the root-level
patterns stopped matching and the real sample configs briefly became trackable.

Before pushing, check that nothing identifying slipped into the staged content —
this greps the *content*, not just filenames:

```bash
git diff --cached -G'<your_sample_identifier>' --name-only
git diff --cached -G'/Volumes|/home/|/media/' --name-only
```

Both should print nothing.

## Archiving results (internal use only — never pushed to GitHub)

This repository never stores patient-derived data, results, or figures —
`results/` is entirely gitignored. For your own longitudinal record across
every sample processed, `scripts/bash/08_archive_results.sh` copies a full,
timestamped snapshot of a run's results to internal institutional storage
(configured separately from this repo via `archive.archive_root` in your
real, gitignored `pipeline_config.yaml` — never commit that value either).

This is a deliberate, separate step — it is **not** part of
`04_run_all.sh`, so it never runs silently:

```bash
bash scripts/bash/08_archive_results.sh
```

Each run creates a new timestamped directory under
`<archive_root>/<SAMPLE_ID>/sv/<run>/` (past archives for the same sample are
never overwritten), copies the exact config used and tool versions alongside
the results for full provenance, generates a SHA-256 checksum manifest
(verified against the archived files immediately after writing), and appends
a summary row (variant counts per category) to a running
`archive_index_sv.tsv` at the archive root — giving a single queryable log
across every sample this pipeline has ever archived, entirely separate from
what's in this repo. `archive_root` is commonly shared with other pipelines
in the suite; the `sv/` tag in the path and the pipeline-specific index
filename keep this pipeline's runs from colliding with theirs.

If `archive.archive_root` is unset or still the placeholder value,
archiving is silently skipped rather than failing — it's opt-in.

## Citation / methods text

`logs/tool_versions.txt` (generated fresh on every run) and
`docs/METHODS.md` together contain what you need for a manuscript methods
section: exact tool versions, filtering thresholds and their rationale, and
the gene-fusion classification approach.
